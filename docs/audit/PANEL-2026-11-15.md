# Code-Review- & Security-Audit-Panel – Pass Captain @ f060845 (2026-11-15)

Gegenstand: das gesamte Plugin (PHP `src/`, Frontend-JS `assets/`, Offline-Scanner-PWA, `uninstall.php`, `pass-captain.php`, readme/Release-Paket).
Arbeitsweise: 7 Prüfer haben nur gelesen bzw. in Wegwerf-Installationen getestet (WP 7.1.4, PHP 8.3, MariaDB 10.11, WooCommerce 11.3, Multisite mit 4 Sites, Datenbank auf ~60-fache Größe hochskaliert). Der 8. Platz (Lead-Developer) hat die Ergebnisse gegengeprüft, Dubletten zusammengeführt und priorisiert. Im Repository wurde während des Audits nichts geändert.

**Ergebnis in einem Satz:** Keine sofort ausnutzbare Lücke für anonyme Angreifer (keine SQLi, kein XSS, keine gefälschten Webhooks, keine vom Client übernommenen Preise) – aber eine Rechteausweitung für Kassenpersonal, mehrere echte Geldfehler in Erstattung/Abrechnung/Rabatt, ein „bezahlt-ohne-Ticket“-Pfad, ein Datenverlust-Szenario auf Multisite und deutliche Performance-Probleme auf der öffentlichen Event-Seite.

## 3. Runde 2 – Risiko-Debatte & Edge-Cases

**SEC-1 – wie realistisch?** *SEC:* „Kassenpersonal ist die am wenigsten vertraute Rolle und genau die hat `wpcap_manage_orders`.“ *LEAD:* „Der Pass geht per Mail an die eigene Adresse, uses_total=0 ist unbegrenzt – das ist ein Selbstbedienungsautomat. Hochstufen auf Kritisch.“ *QA:* „Auch Support-Zugriff vergibt `manage_orders` – damit externe Dienstleister.“ → **Kritisch.**

**QA-1 und der PAY-Verdacht „alter Betrag bei Retry“ sind dieselbe Wurzel:** Der Idempotency-Reuse liefert eine Order zurück, ohne Provider, Items, E-Mail und Betrag mit dem neuen Versuch abzugleichen. *PAY:* „Bei Stripe kommt `amount_mismatch` zurück → Geld weg, keine Tickets.“ *LEAD:* „Ein Fix: Request-Fingerprint speichern, bei Abweichung 409; bei gleichem Fingerprint offene Session nur wiederverwenden, wenn Betrag/Währung passen.“ → **Kritisch.**

**PAY-1 + QA-6 – das 10-Minuten-Fenster:** *QA:* „Hold 30 min, Session 40 min – PAY-1 nutzt genau dieses Fenster, plus SEPA/Banküberweisung mit Tagen.“ *PERF:* „Hold verlängern kostet Kontingent bei ausverkauften Events.“ *LEAD:* „Beides: Session-Ablauf ≤ Hold, und in der Late-Recovery die Kampagne wie die Buyer-Limits neu prüfen (sonst `needs_review`).“ → **Kritisch.**

**PAY-2/PAY-8 – Erstattungen und Chargebacks am Plugin vorbei:** *PAY:* „Der Veranstalter wird für erstattete Bestellungen ausgezahlt – in einer Marktplatz-Konstellation zahlt der Betreiber drauf.“ *PRIV:* „Ohne Gutschrift ist auch die Buchhaltung falsch.“ → **Kritisch**, gemeinsam mit PAY-3/4 (Abrechnung/Belege).

**PAY-5/6 – gestapelte Codes, Kampagne + Gutschein:** *LEAD:* „Selten konfiguriert, aber steuerlich falsche Belege sind kein ‚nice to have‘.“ *PAY:* „Betrag 15 € je Teilerstattung.“ → **Mittel**, aber zusammen mit PAY-4 in einem Paket („eine Quelle der Wahrheit für die Zeilenaufteilung“).

**INT-1 – Datenverlust:** *INT:* „Nur Multisite mit Übernahme und gesetztem Opt-in, aber Ergebnis 103 → 0 Tabellen inkl. Rechnungen.“ *LEAD:* „Selten, aber irreversibel und GoBD-relevant. Kritisch.“

**INT-3 – Subscriptions:** *INT:* „Simuliert, nicht mit echtem WCS.“ *LEAD:* „Die Ursache (Meta wird blind vertraut) ist unabhängig von WCS echt; jedes ‚Order duplizieren‘-Plugin reicht.“ → **Kritisch.**

**INT-2/PERF-12 – QR verschwindet:** *PERF:* „Fremde Plugins mit endroid sind verbreitet.“ *LEAD:* „Ohne QR kein Einlass – Kritisch. Der günstigste Fix ist, die SVG aus der eigenen Bacon-Matrix zu bauen (PDF-Pfad funktioniert bereits).“

**QA-2 – signierter QR nach Verschiebung:** nur mit `signed_qr=1`, aber am Veranstaltungstag fatal. → **Kritisch** (kleiner Fix: Fenster gegen aktuelle Termindaten prüfen).

**PERF-1/2/4:** *PERF:* „1.650 Queries pro anonymem Aufruf sind ein DoS-Hebel, Mollie-Timeouts legen die Seite lahm, synchrones Absagen lässt bei Abbruch Tickets gültig.“ *LEAD:* „PERF-4 ist auch ein Korrektheitsfehler (Revoke nach Refund) → Kritisch. PERF-1/2 → Kritisch für den Release mit Mollie bzw. großen Events.“

**PRIV-1/2/3:** *PRIV:* „PRIV-3 gibt fremde Einwilligungsnachweise heraus und zerstört sie – Art. 7(1) Nachweispflicht.“ *LEAD:* „PRIV-2/3 sind kleine Fixes → Kritisch. PRIV-1 (Fristlöschung) braucht konfigurierbare Fristen → Mittel, aber vor dem Release.“

**SEC-2 / SEC-3:** *SEC:* „CSV-Injection trifft das Einlasspersonal; Fix ist eine Zeile.“ *LEAD:* „Ein-Zeilen-Fix, hoher Schaden → Kritisch. SEC-3 ebenfalls Kritisch: Key mit Schreib-Scopes überlebt Kündigung.“

**Edge-Cases, die alle Fixes abdecken müssen:** MySQL 8 und MariaDB, HPOS an/aus, Multisite (Kontext `switch_to_blog`), Null-Dezimal-Währungen (JPY/HUF), 100-%-Rabatt (Total 0), Mehrverkäufer-Orders (SellerSplit), Late-Webhooks nach Hold-Ablauf, doppelte Webhooks, Retry nach Netzfehler.

**SEC-1 – eine Regel-Validierung für Admin und REST** (`src/Memberships.php`)
```php
/** Validates one rule for the current user; returns the normalized rule or WP_Error. Shared by admin form and REST. */
public static function validate_rule_for_current_user( array $in ) {
	$scope = in_array( $in['scope'] ?? 'event', self::SCOPES, true ) ? (string) $in['scope'] : 'event';
	$is_admin = current_user_can( 'manage_options' );
	if ( 'service' === $scope ) {
		$resource_id = absint( $in['resource_id'] ?? 0 );
		$resource = $resource_id ? ServiceResources::resource( $resource_id ) : null;
		if ( $resource_id ? ! ( $resource && ServiceResources::can_manage( $resource ) ) : ! $is_admin ) {
			return new \WP_Error( 'wpcap_forbidden', __( 'Keine Berechtigung für eine Passregel dieser Ressource.', 'pass-captain' ), array( 'status' => 403 ) );
		}
		return array( 'scope' => 'service', 'event_id' => 0, 'ticket_type_id' => 0, 'resource_id' => $resource_id ) + $in;
	}
	if ( 'any' === $scope && ! $is_admin ) {
		return new \WP_Error( 'wpcap_forbidden', __( 'Regeln für Events und Ressourcen gemeinsam dürfen nur Administratoren anlegen.', 'pass-captain' ), array( 'status' => 403 ) );
	}
	$type_id = absint( $in['ticket_type_id'] ?? 0 );
	$event_id = absint( $in['event_id'] ?? 0 );
	if ( $type_id ) {
		$type_event = (int) Events::event_of_ticket_type( $type_id );
		if ( ! $type_event || ( $event_id && $event_id !== $type_event ) ) {
			return new \WP_Error( 'wpcap_pass_rule_scope', __( 'Die Ticketart gehört nicht zum gewählten Event.', 'pass-captain' ), array( 'status' => 400 ) );
		}
		$event_id = $type_event;
	}
	if ( $event_id ? ! Access::can_access_event( $event_id, 'wpcap_manage_orders' ) : ! $is_admin ) {
		return new \WP_Error( 'wpcap_forbidden', __( 'Keine Berechtigung für eine Passregel dieses Events.', 'pass-captain' ), array( 'status' => 403 ) );
	}
	return array( 'scope' => $scope, 'event_id' => $event_id, 'ticket_type_id' => $type_id, 'resource_id' => 'any' === $scope ? absint( $in['resource_id'] ?? 0 ) : 0 ) + $in;
}
```

Regressionstest: Kassierer von Event A → `service`/`resource_id=0`, `any`, fremde `resource_id`, fremde `ticket_type_id` → je 403.
